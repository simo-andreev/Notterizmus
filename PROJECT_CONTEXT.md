# Notterizmus — context for coding agents

## Purpose
- GNOME desktop outline editor for book chapter notes; output is pasted into TopCoding's notes editor (`app.topcoding.bg/assignments`). Snapshot: v1.6.0, 2026-11-19.
- Plans and their IDs (R1, R2, …, used below and in commit messages) are in ROADMAP.md.
- Single main user: Ubuntu 26.04 (`resolute`), GNOME 50, Wayland, locale `bg_BG.UTF-8`, notes in English and Bulgarian.
- Distributed as a Debian package via `ppa:simeonandreev/ppa-library`; GPL-3.0-or-later.

## Rules
- Use the platform's native stack: Python 3.11+, PyGObject, GTK 4, libadwaita (≥1.8), Enchant via ctypes, WebKitGTK 6.0 (drawings only). No pip dependencies.
- Keep `model.py`, `rules.py`, `layout.py`, `export.py`, `importer.py`, `spell.py`, `completion.py`, `paths.py`, `guide.py`, `library.py`, `backups.py`, `commands.py`, `find.py`, `drawing.py`, `lexical.py`, `gpu.py`, `files.py`, `state.py`, `assessment_txt.py`, `assessments.py` free of GTK so they stay unit-testable.
- The versions of the GTK libraries are declared once, in `notterizmus/ui/__init__.py`, which runs before any UI module, so each can be imported on its own without a PyGIWarning. A library newly imported from `gi.repository` needs a line there (`tests/test_gi_versions.py` checks), except GLib, GObject and Gio.
- When a control or shortcut changes, update the Getting Started chapter (`guide.py`) as well as README.md, FEATURES.md and the shortcuts dialog. Keys live in `commands.COMMANDS` (CR37). `tests/test_guide.py` fails if the guide teaches a key that README.md doesn't mention or the command table doesn't have, or if the guide gains a word the English dictionary flags (add it to `guide.SPELL_IGNORE`).
- The app's folders come from `paths.py`: `config_dir()`, `data_dir()`, `cache_dir()` (each `<XDG base>/notterizmus`, the base from `$XDG_…_HOME` when set and not empty, else under the home folder) and `data_dirs()` for `$XDG_DATA_DIRS`. Don't read those variables anywhere else (CR40).
- To ask whether a node holds text, use `model.is_text(node)` (heading or bullet), never `kind != "table"`: kinds from a newer version are neither.
- Never drop data the code doesn't understand: `Node.extra` carries unknown fields of known kinds, and unknown kinds keep their whole JSON; both are saved back unchanged. The same holds for the file itself: `Document.extra` and `Document.chapter_extra` carry unknown fields of the file and of its `chapter` entry, and `Document.format` its format name (a file from a newer version keeps `notterizmus/2`).
- `Document.load` raises `OSError` for a file it can't read and `ValueError` for one that isn't a chapter (not JSON, or JSON of the wrong shape: `from_json` turns the `AttributeError`/`TypeError`/`KeyError` of a mis-shaped file into it). Catch both wherever a chapter file is read or rewritten, `library` calls included; anything else escapes the handler, and from `Window.__init__` (the last chapter open) it keeps the app from starting.
- The editor is `ui/outline.py` (the widget: rows, refresh, focus, scrolling) plus mixins `ui/outline_*.py`, one theme each (`undo`, `keys`, `items`, `selection`, `clipboard`, `menus`, `assist`, `carets`). They share `self`; put new editor methods in the matching mixin, and key handling in `outline_keys.on_key` / `common_key`.
- The window is `ui/window.py` (building the window, the open chapter, spelling, copy and find) plus mixins `ui/window_*.py` (CR38): `saving`, `chapters` (chapter and book files), `dialogs`, `zoom`, `sizing` (the chapter list's width). Put new window methods in the matching mixin; what each keeps and uses is in its module's docstring. `notes_root()`, `load_state()` and `save_state()` are in `ui/helpers.py`.
- Every document mutation in the editor goes through `with self._op():` or `self._commit(group)` (`ui/outline_undo.py`), and the change itself happens inside it, not before (CR39); code outside the editor (a table row, the find bar) uses `with editor.change():`. Otherwise it is neither undoable nor autosaved. The state the mixins share is listed in `outline.py`'s docstring, with the module that changes each.
- Never remove and re-append row widgets: `refresh()` reorders children in place (`reorder_child_after`) and reuses rows by node id and spacer labels. Re-adding rows makes the text jump (bug reported and fixed).
- Scrolling follows the cursor via `ensure_visible()` (tick callback, retried until new rows are laid out); the viewport's own `scroll_to_focus` is off. Every new text view must be registered with `track_cursor()`.
- New text views: call `size_new_views()` (min height = one line); `refresh()` re-measures them 20 ms later, since GtkTextView measures its height before it knows its width. Only rows that are new or whose prefix changed are re-measured (`_remeasure_rows`, one pending timeout for any number of refreshes): every view of a 500-item chapter after each Enter or Tab was 500 re-measures (CR33). `_requeue_views()` re-measures them all, after a zoom.
- Popups are freed once closed: a menu built by `_popup` goes through `helpers.let_go_when_closed(pop, controllers…)`, and a popover class connects its own methods through `helpers.weak_handler` (`AssistPopover`); a handler that held its popover kept it, and what it pointed at, until the app quit. `editor._ctx` holds its view through a weak reference. `tests/ui/test_freeing.py` checks both kinds.
- Handlers on widgets inside a row find the row when the event comes (`rows.row_of`, `source.get_widget()` in the sidebar's drag handlers) and never hold it: a held row makes a cycle through GTK that Python's collector can't see, and the row stays until the app quits (R29c for the editor's rows, CR18 for the chapter list's).
- A laid-out text view about to change width (e.g. its row's prefix did: `TextRow.set_prefix`) gets `RichText.expect_width_change(delta)`. GtkTextView reports the height for the width it was last laid out at (and constant-size request mode), so that frame would draw the old height and the rows below would jump a frame later; until its next allocation, `do_measure` answers `height_for_width()` (Pango, matches GtkTextView exactly). Don't declare HEIGHT_FOR_WIDTH instead: GtkBox then reports min > natural heights (GTK warnings).
- Data a widget carries is an attribute of its own class, never one stuck on a plain GTK widget (CR43): the chapter list's `BookRow`/`ChapterRow` (`book`, `folder`, `path`; window.py asks `ChapterSidebar.focused_target()`), `MenuRow` for the editor's popup lists, `CommandRow`, `VersionRow`, `PrefixLabel`, and `drawing_web._PageView` for the page's load state.
- Spell checking belongs to the editor: `OutlineEditor.spelling` (a `richtext.Spelling`, set by `set_spelling()`) is passed to every `RichText` a row makes; a view made without it doesn't check (CR41).
- A one-shot `GLib.idle_add`/`timeout_add` callback goes through `ui/helpers.run_once(fn, *args)`, and a CSS class that follows a condition through `set_class(widget, name, on)`; not `lambda: (f(), False)[1]` or `(w.add_css_class if c else w.remove_css_class)(…)` (CR48).
- Don't use `Gtk.PopoverMenu` for app menus (it mis-measures and scrolls); use `OutlineEditor._popup()` / `popup_menu()` (ListBox popover, `ui/outline_menus.py`). Rows that are `MenuRow(choice=True)` get number hotkeys 1–9, 0 from `_number_rows()`; keep that for any new popup. Exception: Search Commands, where digits are typed into the search. The right-click menu is GtkTextView's own, extended via `set_extra_menu` in `_prepare_context()`.
- Text rendering: `ui/app.use_hinted_text()` switches GTK's `gtk-font-rendering` from automatic (unhinted) to manual, so the desktop's hinting applies; unhinted, thin strokes fall between pixel rows (the top bar of "=" all but vanished on the user's screen). Don't remove it.
- Roman numerals are the single Unicode characters `Ⅰ`–`Ⅻ` (user requirement), composed beyond 12 (`ⅩⅢ`).
- When a version changes, update: `notterizmus/__init__.py` `VERSION`, `data/*.metainfo.xml` `<release>` (also the About dialog's release notes), `CHANGELOG.md` (between releases, changes go into an `## Unreleased` section at its top; `scripts/release.sh` refuses to build while it is there), `debian/notterizmus.1` header, `debian/changelog` (via `dch` with `DEBEMAIL` = maintainer email), and the "Notterizmus X.Y" titles of README.md and FEATURES.md. `tests/test_release.py` enforces it.
- `APP_ID = dev.simo.Notterizmus` is also the icon name, desktop-file name, metainfo id and Wayland app id; keep them identical.
- Ask before pushing, uploading to the PPA, or publishing anything; commit only when asked.

## Facts and decisions
- Tree: `Node` kinds `root`, `heading` (numbered), `bullet` (marker `dot`/`plus`/`minus`/`important`/`question` or user-defined), `table` (`data.rows` = rows × cells × runs, `data.header`). Text is a list of `Run(text, bold, italic)`.
- `can_contain`: headings only under root or headings; bullets/tables under headings or bullets. A top-level item can be a bullet (your decision on CR11, 2026-11-19): `set_kind`, the item-type menu, Ctrl+Shift+Space and a paste make one there. A bullet that moves up to root becomes a heading, the next numbered item: outdented there, or promoted when its top-level parent is deleted (`outdent`, `remove_promote`). Layout sets a top-level bullet after a numbered item apart with the blank line between top-level items. A typed trigger changes the kind first and is deleted only when that worked (CR20).
- Layout defaults reproduce the user's sample exactly for tree sections: bullet column = label column + 5; spacer `│` line before each numbered child unless the previous sibling is a bullet; bullets (tables, drawings) that follow a numbered sibling get a spacer before and after the run, so they don't read as that sibling's (`tree.spacer_around_parent_leaves`, on by default; after the last numbered child the trunk has ended, so that spacer is an empty line); blank line before each top-level numbered item, and before a top-level bullet that follows one.
- File format: JSON `{"format": "notterizmus/1", book, chapter{number,title}, lang?, content[]}`, `.notz`, saved atomically (a save that fails removes its temporary file), autosaved 800 ms after changes. Path: `<XDG Documents>/Notterizmus/<Book>/<NN> <Title>.notz` (localized folder, e.g. `~/Документи`).
- `~/.config/notterizmus/state.json`: `last_file`, `last_book`, `spell`, `spell_lang`, `sidebar`, `sidebar_width`, `zoom`, read and written by `state.py` (no GTK): a file that isn't a JSON object counts as empty, a setting of the wrong kind is left out so the window's default applies (such a file stopped the app from starting, CR22), and saving goes through `files.atomic_write`. `rules.toml` overrides `rules.DEFAULTS`; `Rules.load` checks the result (`rules._problem`: sections are tables, values have the default's type, markers have a symbol, no marker has the numbered item's trigger or another marker's, `numbering.levels` names known formats, CR23) and, for a file that is not TOML or fails the check, reports it in `.error` and uses the defaults alone (such a file used to stop the app from starting). Settings it doesn't know are kept.
- Undo: whole-document JSON snapshots, except that drawings' data is left out of the text and shared between snapshots (`outline_undo._content`; R29d). That relies on a drawing's `data` never being changed in place: an edit gives the node a new dict. Typing groups per word (`RichText.last_edit` → `_text_group`); GtkTextBuffer's own undo is disabled. History resets on load. `OutlineEditor.cur_view` is normally set by a row's focus-enter handler; `_focus_node` also sets it, because after an undo the focus is often still in the same (reused) row and no focus event follows.
- Enter on an empty bullet under a heading converts it to the heading's next sibling (Ⅰ.1.a + bullets → Ⅰ.1.b); Ctrl+Enter does the same from anywhere.
- Multi-cursor: Ctrl tapped twice within 0.4 s and held, then ↑/↓; extra carets are GtkTextMarks drawn in `do_snapshot_layer`.
- Chapter sidebar (R1): `Adw.OverlaySplitView` with `ui/sidebar.ChapterSidebar`; `library.scan(notes_root())` reads book folders and `<NN> <Title>.notz` names (not the JSON). It rescans when a chapter opens, when the sidebar is shown and when the window becomes active. Its width is fixed (`min = max = state["sidebar_width"]`, default 260, 180-520) and set by `Window.set_sidebar_width()`, which also moves the collapse breakpoint to "list + text column minimum + 20 px"; collapsing into an overlay doesn't change the saved `sidebar` choice. The split view has no resize handle, so `Window.handle` is an overlay strip over the edge; the drag gesture sits on the overlay (stationary, so offsets don't jitter) and claims only after 3 px of movement, so the handle's double-click (reset) isn't cancelled. `win.prev-chapter`/`win.next-chapter` (Ctrl+PgUp/PgDn) are app accels and also handled in `OutlineEditor.common_key`, so GtkTextView can't take them.
- Renaming and reordering (R2, R28): `library.set_chapter` / `renumber` / `reorder` / `rename_book` change files and return `{old path: new path}`. `renumber` reads every chapter before it stages any (one that can't be read must not leave the others under their hidden staging names); `rename_book` moves such a file along untouched. Call `Window._flush_save()` before and `_after_move(moved)` after, which re-points the open `Document` (path, book, number, title) and `last_file`; otherwise autosave recreates the old file. Chapter numbers are the real book's, so reordering permutes the existing numbers and a taken number is swapped, never invented. Renumbering stages files under hidden `.moving-*.notz` names, which `scan()` skips. Trash goes through `window._trash_file` / `_restore_from_trash` (UI tests swap in a scratch Trash: `/tmp` is tmpfs, so the real Trash would collect test files in `/tmp/.Trash-1000`).
- Text size (R5): `Window.set_zoom()` writes `font-size` for `.outline .prefix, .outline textview.rt` into one app-wide CSS provider above style.css (one per window would pile up on the display; a closed window's would win). It calls `OutlineEditor.text_size_changed()`, which drops the rows' one-line minimum height and forgets `_line_h`; don't re-measure in the same frame, because the new font only takes effect in the layout phase. Ctrl + scroll goes through `Window.scroll_zoom(ctrl, dy)`.
- Find and replace (R3): `ui/findbar.FindBar` (a `Gtk.SearchBar` under the header) matches with `find.find_all` in every text view in outline order (`display_order` → `row.views()`), highlights with each RichText's `tag_found` / `tag_found_current`, and selects the current match in its view (so Esc leaves the cursor there). Replacing uses `RichText.replace_range` (keeps the first replaced character's bold/italic) inside `editor._op()`, so Replace All is one undo step. It refinds 200 ms after the editor's `changed` signal. Escape: a capture controller on the bar closes it from any of its widgets; in the text, `OutlineEditor.on_escape` (set by the window) closes it after multi-cursor and item selection have had their Escape.
- Drag selection (`outline_selection.py`): a left-button drag starts as GtkTextView's text selection; once the pointer is over another row it becomes an item selection (anchor = the row pressed, head = the row under the pointer), and back over the first row the outline selects the text itself. GtkTextView's gestures claim the pointer, which denies gestures on the outline, so the outline follows the drag with a capture-phase `EventControllerMotion` and an `EventControllerLegacy` (for the release; PyGObject passes its event as None, so read `get_current_event()`), and denies the text view's `GestureDrag` when it takes over. Autoscroll runs on a tick callback within 30 px of the top/bottom edge.
- Item selection (`OutlineEditor.sel`) is exactly the items covered, in outline order: a parent doesn't stand for its sub-items (it used to, so a drag or Shift+↓ ending on a heading deleted its whole section; reported as a bug). Delete and cut go through `model.remove_items` (sub-items not selected move up, as with `remove_promote`), copy through `model.selected_json`; Tab moves `_top_level(sel)` with everything under them. Ctrl+W goes item → item with its sub-items → the parent's → everything (`_scope_around`).
- Primary selection: a search field that selects its own text takes the primary selection, which collapses the chapter's text selection to its end. Capture the cursor/selection before focusing such a field (`FindBar._anchor`, the `before_run` restore in Search Commands). Search fields use `search_delay=0`, and Enter catches up if it arrives before the list or the matches did, so Enter right after typing acts on what was typed.
- Search Commands (R24, Ctrl+Shift+P): `ui/command_search.build(win)` lists what's available now (window actions that are enabled; editor commands only while the window has a chapter open, since the editor keeps its last chapter after one closes), `commands.search()` ranks them. Key-only editor behaviours are replayed with `OutlineEditor.on_key(row, view, keyval, state)` using GTK's key names (Shift+w → `W`, Shift+Tab → `ISO_Left_Tab`). The chosen command runs on the dialog's `closed` signal, after focus is back in the editor. New commands and keys go into `commands.COMMANDS` (CR37): the app's accelerators, Search Commands and the Shortcuts dialog (`commands.SHORTCUTS`) are made from it; `tests/test_commands.py` fails if one of its keys is missing from README.md.
- Earlier versions (R4): `backups.py`; copies in `paths.backups_dir()/<Book>/<chapter stem>/<YYYY-MM-DDTHH-MM-SSZ>.notz`, named in UTC since local time has an hour twice a year (CR26; older copies' names are local time without the Z and are still read). `Backup.when` is local time with its offset, so copies sort by when they were taken. `Window.set_doc` takes a forced copy on open; `Window.save` copies the on-disk file before overwriting it at most every `backups.BACKUP_EVERY` (600 s), skipping identical copies, then `backups.thin()` keeps all of the last day, one per hour for a week, one per day for 90 days and one per ISO week after (`TIERS`, newest per slot; ages are real elapsed time, slots local hours, days and weeks). `backups.keep(data, folder)` stores a version that isn't on disk and never drops it for a copy in the same second. Not for the guide. `_after_move` moves the copies with renamed chapters; `backups.move` puts every moving folder aside under a hidden name first, so chapters that swap names keep their own copies (CR5). Restore = `OutlineEditor.replace_content(root)`, one undo step.
- Saving (CR4, CR10, CR25): `Document.save` writes through `files.atomic_write` (fsync the file, replace, fsync the folder; the file keeps its mode, a new one follows the umask) and remembers the file's inode, mtime and size; `Document.changed_on_disk()` compares. `Window.save()` asks Reload or Keep Mine (`_ask_about_disk_change`) instead of overwriting a file another program changed; where no answer can wait (`save(ask=False)`: `_flush_save`, closing the window) it keeps this version and puts the other in Earlier Versions. Code that writes the open chapter's file another way calls `doc.remember_disk()` afterwards, as `_after_move` does. A chapter that replaces the open one goes through `open_path` or `set_doc`, which first write an autosave that is still waiting (`_save_pending`), before the new file is read. `save()` returns whether the chapter is on disk. When the save on close fails (RV1), `_on_close` keeps the window open, writes the chapter to `paths.unsaved_dir()` (`backups.keep_unsaved`) and asks Retry, Save a Copy… or Quit Without Saving; anything that closes the window on purpose after that goes through `_close_now()`, which UI tests replace so the shared window stays. A failed save calls `_saved_state(error)`: `save_banner` (an `Adw.Banner` with Retry) and a "• " before the title, retries after 2, 4, 8 … s (at most `RETRY_MAX`), all cleared by the next save that works, `set_doc` or `_close_doc` (RV2). Autosaves that fail show no toast; errors are reported through `_why(e)` (the `strerror`, not the temporary file's name). `_save_pending` also flushes while a save has failed, and `set_doc` writes the chapter aside (`_put_aside_before_leaving`) when that flush fails (RV34).
- Renumbering (CR6): `library.renumber` writes each chapter under a hidden `.moving-*.notz` name with its new number, then renames them; on any error it puts every chapter back under its old name and number (`_put_back`, which never overwrites a chapter). `set_chapter` makes every check before anything moves and undoes its swap if the final rename fails. A crash halfway leaves `.moving-*` files: `library.stranded()` finds them, `restore_stranded()` names them from their content, and the window offers that at start-up and after a failed change (`_offer_stranded`).
- The cursor's order is `model.editable_order()`: `display_order()` without the sub-items of blocks from a newer version, which have no rows (CR12).
- A toast whose button acts on the editor's last change (the paste toasts) checks `unchanged_since(undo_mark())` first, since `undo()` takes back whatever came last; the window dismisses it on the editor's next `changed` (`Window._editor_toast`, CR3).
- Paste labels (`importer.LABEL_RE`): a label of one part is a number, a roman numeral (Unicode, or Latin like iv, XII) or a single Latin or Cyrillic letter, so "Yes) …" stays text (CR24); in a dotted label ("Ⅱ.1.ab)") letter parts may be longer, and when the rules number the top level with letters, so may a single part. Tables are square once read (`model._table_dec` pads short rows; CR47).
- Toasts and libadwaita rows treat their text as Pango markup unless told otherwise (`use_markup` defaults to true for `Adw.Toast`, `Adw.ActionRow` and `Adw.ComboRow` in libadwaita 1.9): give them `use_markup=False` when the text holds a title, a file name or an error (CR8). Plain `Gtk.Label(label=…)` is fine; markup built from text goes through `GLib.markup_escape_text` (`rows._prefix_markup`).
- Book folders come from `library.safe_name()`: never hidden, ".", ".." or over 255 bytes (CR7, CR15); `chapter_filename()` shortens a long title in the file name only (`model.fit_name`). New Chapter finds a taken number with `library.chapter_numbered()` (CR16) and asks again, as typed, when the file can't be written.
- Item selection always has ends: `set_selection()` sets `sel_anchor`/`sel_head` to its first and last items unless the caller set them inside it; Shift+click falls back to the current item when the anchor is gone (CR2).
- Ctrl+B/I with nothing selected keeps its pending format while the cursor is set again at the same offset (`RichText._pending_at`): input methods do that before they type (R32, CR9).
- A drawing's Done acts only on the chapter it was opened from, and while the drawing window is open `App.do_open` brings it to the front instead of opening the file (`OutlineEditor.drawing_window()`, CR19).
- Getting Started (F1, `win.guide`): `guide.document()` writes a fresh copy to `paths.guide_path()` (`$XDG_DATA_HOME/notterizmus/`, outside the notes folder) each time it's opened; `Window._is_guide()` gives it its own title, keeps `last_book` unchanged and passes `guide.SPELL_IGNORE` only while the guide is open (`Speller.ignore_while_open`; Enchant's session list would keep them for every chapter after it, CR21). F1 used to open About.
- Drawings (R12, decided 2026-11-17: embedded Excalidraw): a `drawing` node's `data` is the Excalidraw scene `{elements, appState, files}` (`drawing.py`, no GTK). `ui/drawing_web.py` is the only module that touches WebKit; the rest of the app calls its `edit()`, `render()` and `available()` (the UI tests replace the first two). The page is `notterizmus/drawing_web/` (built from `web/drawing` by `scripts/build-drawing-editor.sh`, committed because package builds have no network), served through the app's own URI scheme `notterizmus-draw://app/` with a CSP that allows no network, no frames, objects or forms (`frame-src 'none'` and the like; pictures need `img-src data: blob:`, CR31); the view's session is ephemeral, download responses are refused and downloads the page starts are cancelled. `index.html` hides what the page can't do: the shape library's button (it needs browser storage) and, in More tools, Mermaid to Excalidraw (`mermaid-stub.js`) and Web Embed, by their shared `data-testid` (CR29); a WebKit test checks both, and that pictures load and frames don't. `javascript_can_access_clipboard` stays on until copying and pasting in the drawing window has been tried without it.
- The page's `changed()` (Cancel asks first when it's true) compares the scene version over every element, deleted ones included, and the kept view state, with those at `open()` (CR17); `elements()` and `updateScene()` are for the UI tests. `scripts/build-drawing-editor.sh` starts with `npm ci`, which downloads every package again; with `node_modules` already matching the lockfile (`npm ls --offline`), its other steps rebuild the page offline.
- Drawing previews are PNGs in `$XDG_CACHE_HOME/notterizmus/drawings/<preview_key>.png` (a sha1 of the scene and `drawing.PREVIEW_VERSION`), never in the chapter file. They have 2 pixels per unit of the drawing, but no more than `drawing.PREVIEW_PIXELS` (twice `PREVIEW_MAX`, the largest size a drawing is shown at); Python passes that limit to the page's `open()` and `render()`. Raise `PREVIEW_VERSION` when previews are made differently, so cached ones are made again. A missing one is rendered on a hidden web view (`drawing_web.render`) from the scene; without WebKit the row shows a note instead.
- WebKit lessons: a JavaScript call made before the page's `load-changed: FINISHED` is dropped ("Completion handler … no longer reachable"), so `_call` queues until then; `call_async_javascript_function` rejects boolean arguments ("Invalid parameter"), so everything is passed as text; Excalidraw's API object exists before the scene has loaded, so `ntz.open()` waits for `appState.isLoading` to clear; Excalidraw drops elements without a size, so test scenes give text a width and height.
- Freeing windows and widgets (R29a, R29c): GTK 4 hides a closed window without disposing of it. A handler that holds a window, a row or a text view (a lambda using `self`, a bound method) and is connected on something that object owns (a child widget, an event controller, a text buffer) makes a cycle through GTK that Python's garbage collector can't see, so all of it stays until the app quits. Handlers connected on the object itself are fine, because PyGObject shows those to the collector. So handlers on a row's widgets find their row when the event comes (`rows.row_of`, `rows._in_row`), and handlers on a view's buffer hold the view weakly (`richtext._weak`, `OutlineEditor.track_cursor`); holding the editor is fine. `tests/ui/test_freeing.py` checks that rows are freed after a chapter switch, a delete and a table rebuild. In such a test, a local variable left pointing at a widget (a loop's last item) keeps it alive too. A window also keeps a strong reference to its focus widget after that widget is taken out. `DrawingWindow._release` ends the web process, clears focus and drops the content. To check that something is freed, use `obj.weak_ref(callback)` (keep the handle it returns, or the weak ref is dropped) and `gc.collect()`. Once no web view is left, WebKit's default web context is freed only by a C exit handler, after Python has stopped. Freeing it there frees the Python URI scheme handler, and the process segfaults as it quits; in a UI run that shows as exit 139 after every test passed. So `drawing_web` makes its own context (`_context`), which Python frees while it shuts down.
- GPU drawing on NVIDIA (R29f): Ubuntu's WebKitGTK carries a Debian patch that turns the GPU off when NVIDIA's own driver is loaded, so pages are drawn on the CPU (a stroke in a large drawing window: 8 frames a second). `gpu.prefer_gpu` (no GTK) sets `WEBKIT_FORCE_DMABUF_RENDERER=1` when `/proc/driver/nvidia/version` exists and none of WebKit's own switches is set; `WEBKIT_DISABLE_DMABUF_RENDERER=1` turns it off. `webkit://gpu` in a web view shows the policy WebKit chose. GTK's Vulkan renderer can't import the compressed buffers WebKit then makes, so it copied each frame through GL and the CPU (`GDK_DEBUG=dmabuf` shows it; the app at 120–190% CPU while drawing); so the same function sets `GSK_RENDERER=gl` for the whole app unless it is set (9% CPU). Both are read once, at the first page and the first window, so `ui/app.py` calls it at its top, before it loads GTK, and `scripts/measure-drawing-stroke.py` does too; no other module may change the environment when it is imported (`tests/test_gpu.py` checks both). `scripts/ui-tests.sh` names its displays' renderers (`broadway`, `cairo`) so the tests don't depend on the machine's driver.
- Blurry canvas in wide windows (R29g): WebKit 2.52's compositor draws a canvas wider or taller than 2048 pixels about half a pixel off when that size is odd (only on the GPU path; WebKit bug 317744 looks like the cause). `drawing_web._EvenSize` gives the web view an even width and height. To compare sharpness, capture the view with `Gtk.WidgetPaintable` and the window's renderer (`render_texture`): the app can't take screenshots of the desktop (GNOME allows only its own tools).
- On this machine `libwebkitgtk-6.0-4` is installed but its typelib isn't: `sudo apt install gir1.2-webkit-6.0`. Without it the app runs and says what is missing when a drawing is opened. The real-Excalidraw UI tests run with `NOTTERIZMUS_UI_WEBKIT=1 scripts/ui-tests.sh` (they work on Broadway).
- Unknown kinds (R6): `layout` emits a `Line("unknown")` and skips their children, the exporters drop those lines, spacer decisions ignore them, the editor shows `rows.UnknownRow` (read-only note with a delete button, no text view, skipped by the cursor).
- Ctrl+Space (`OutlineEditor.show_assist`): completions from `completion.py` (chapter words, then other `.notz` in the book folder via `BookWords`, then the Hunspell `.dic` stems for the word's alphabet), plus spelling fixes. Spelling fixes are hidden while the cursor is at the end of a word that has completions (an unfinished word always looks misspelled). Ctrl+Shift+Space cycles item type.
- Clipboard MIME types: internal `application/x-notterizmus-nodes+json` and `-runs+json`, plus `text/html` and `text/plain`. A copy with a drawing also carries TopCoding's editor JSON (`application/x-lexical-editor`) packed into `chromium/x-web-custom-data` and `application/x-moz-custom-clipdata` (`lexical.clipboard_data`); Ctrl+V reads those two right after the app's own types.
- Paste from TopCoding: after the app's own types, Ctrl+V reads `chromium/x-web-custom-data` / `application/x-moz-custom-clipdata` and uses the Lexical JSON in it only when it holds a non-empty drawing (`lexical.pasted_items`: the same items as `importer.html_items` plus `("drawing", data)`, the scene cut down by `drawing.from_scene` as the drawing window saves one); otherwise, or when it can't be read, the paste goes on to the HTML as before. Drawings are placed like tables (`importer.block_nodes`, `ClipboardMixin._insert_blocks`). This also brings drawings back from the app's own Copy for TopCoding.
- Paste: `importer.parse()` returns `None` for text without outline markers → it is joined into the current item (user wants long text in one item); Ctrl+Shift+V always joins. A table is not a marker: tables that come without any (`importer.table_nodes`) are put after the item, where Ctrl+T would put one (`ClipboardMixin._insert_tables`), in the same undo step as the text.
- Spelling: Enchant/Hunspell via ctypes because the `gir1.2-spelling-1` typelib isn't installed. Primary language comes from the chapter text, not the locale (the `bg_BG` locale once marked all English red). Words in the other alphabet use a matching dictionary.

- Assessments (R35, 2026-11-25): a TopCoding chapter assessment, practised from the `.txt` its report page downloads, the only source (the app never contacts TopCoding and doesn't grade). `assessment_txt.parse` reads the file the page's own script writes (template in its docstring): graded downloads have `Final result:` in the header and `Score: x / 1` in every question, `Feedback:` only where the score is above 0; ungraded ones have none of these. `Completed:` is the browser's `toLocaleString()`, so several forms are read (bg, de/ru, en-GB, en-US, ISO). A report's identity (`Report.key`) is its title and completion time, the same for both downloads. Anything else raises `ReportError` with the line and question, and nothing is imported; a file cut short is caught by its missing final line break, a graded question without a score, points that don't add up to the final result, or a last question without the sample answer the others have (an ungraded file cut exactly between questions can't be told). Raise `PARSER_VERSION` when `parse()` reads a file differently: stored reports are read again from their `report.txt`.
- Assessments are stored by `assessments.py` in `<notes folder>/.assessments/<id>/` (`paths.assessments_dir()`; hidden, so `library.scan` skips it): `report.txt` byte for byte, `report.json` (format `notterizmus-assessment/1`: the parsed report, the chapter `Link` {file relative to the notes folder, book, number, title}, the parser version, the source file name, the import time and `sha256` of `report.txt`), `draft.json` (format `notterizmus-attempt/1`) and `attempts/<UTC stamp>Z.json`. Imports are staged in `.importing-<hex>` and renamed into place; Replace writes `report.txt` first and `load()` re-parses when the sha256 disagrees; Finish writes `finished` into the draft, then renames it into `attempts/`, and `read_draft` completes a finish that stopped between. A draft whose disk state (inode, mtime, size) changed since this computer read or wrote it is kept as an attempt with origin "another computer" before ours is written. Unknown fields are kept everywhere. Links follow the app's own chapter moves through `follow_moves` (called in `_after_move`) and others' by `resolve` (file, then title or number in the book, then title anywhere; `resolve_links` rewrites a link found other than by its file).
- `ui/helpers.WORKER` is the app's one background thread (a `ThreadPoolExecutor(1)`): assessments' files are read, parsed and written there, in order, with results handed back through `GLib.idle_add`. Jobs never touch GTK; `WORKER.pending` lets UI tests wait for them, and `WORKER.wait()` blocks until they're done (closing the Assessments window). The practice page copies the answers on the main loop and its `DraftFile` (used only on the worker) carries the draft's disk state between writes.
- Assessments window (`ui/assessments_window.py`): an `Adw.ApplicationWindow` around an `Adw.NavigationView`, with the list (reports by book and chapter) and at most one `assessment_page.PracticePage` pushed over it. It is a window of its own, not a dialog or a page of the main window, because practice runs up to an hour beside the notes or instead of them, so it is moved, tiled and resized on its own. It is the main window's child by ownership only: it has no `transient_for`, so it doesn't stay above the notes. Ways in: the main menu (Assessments… opens the open chapter's newest assessment, else the list; Import Assessment Report…), Search Commands, and each chapter row's assessment button and right-click menu in the chapter list (`win.chapter-practice` when the chapter has an assessment, else `win.chapter-import`). Importing: `choose_file(chapter)` → file dialog → `WORKER` reads and parses the file and looks for the same report → a duplicate asks Skip/Replace (Replace keeps the old link), an import for a chapter (`Import.for_chapter`) goes with that chapter without asking, any other asks with `chapter_dialog`, offering `store.suggest`'s match → staged write on `WORKER` → `_imported` shows a toast, calls `on_changed` and opens the practice page.
- Its lifecycle: the main window creates it on first use (`Window.assessments_window()`, which presents the same one after that), keeps it in `_assessments`, hears of imports and links through `on_changed` (`refresh_linked`, which also updates the chapter rows' buttons) and of its closing through `on_closed`. The app has one main window (`App.win`), so there is one Assessments window. Closing the main window (`_on_close`) saves the chapter and closes this one, whose `close_request` writes the draft first (`flush(wait=True)`); if that write fails, it stays open asking Keep Open or Close Anyway, and the app quits once it closes, as both are windows of the same application. Closing it alone leaves the notes open. The same assessment can't be open twice: the one window holds one practice page, and `open_assessment` returns to it for the same assessment, or pops it (saved, then let go) before pushing another. The window and its page let go of their widgets when they go (R29), as `tests/ui/test_assessments.py` checks.

## TopCoding target
- The editor is Lexical (namespace `SummaryEditor`) rendered in proportional Roboto; it has native table and `excalidraw` nodes.
- Pasted HTML keeps whitespace only inside `white-space: pre-wrap` spans; `<strong>`, `<em>`, `<br>`, `<table>`, `<th>` survive; `font-family` styles are stripped; `<code>` survives as inline code with a background (rule `export.code_prefix`).
- `export.to_html` writes one `<p>` with `<br>` per line, breaking only for tables; real pastes of this format are confirmed good by the user.
- Testing paste in the browser: dispatch a synthetic `ClipboardEvent('paste')` with a `DataTransfer` on `[data-lexical-editor]`; never click Save/Submit there; restore with `editor.setEditorState(...)`. Tests in TopCoding's interface go to chapter 999 of assignment 2522 (`app.topcoding.bg/assignments/2522/chapters/999`), which the user made for them on 2026-11-19. Chapters 11, 12 and 15 hold real work (12 was the scratch chapter until 2026-11-18) and must never be used for tests; for any other page, ask first.
- Drawings (checked 2026-11-17 in what was then the scratch chapter): the `excalidraw` node has no `importDOM`, so HTML can't carry one. Its JSON is `{type: "excalidraw", version: 1, data: "<JSON text of {elements, appState, files}>"}`, a block node. A paste whose `application/x-lexical-editor` is `{namespace: "SummaryEditor", nodes: [...]}` is used instead of the HTML; `lexical.to_nodes` writes paragraphs, tables and drawings in the shapes the editor makes from our HTML (text `format`: 1 bold, 2 italic, 16 code; adjacent same-format text merged; `<th>` cells get `headerState` 3 in the first column and 1 elsewhere from HTML, and `lexical._header_state` writes the same, CR28). The app adds this format only when the copied lines contain a drawing.
- Firefox ignores `chromium/x-web-custom-data`; it reads its own `application/x-moz-custom-clipdata` (`lexical.moz_custom_data`), confirmed on Firefox 160 by a WebDriver Ctrl+V (geckodriver, Firefox and the clipboard owner both on X11: under Wayland an unfocused owner can't take the clipboard) whose paste event got `application/x-lexical-editor` intact.

## Verifying changes
- Unit tests: `python3 -m unittest discover -s tests -t .` (also run during the Debian build). They cover the non-GTK modules; the UI suites skip themselves there. The build has no PyGObject (Launchpad installs only the Build-Depends), so a module in `tests/ui` imports GTK and the app's UI modules only inside its tests, never at its top, and a plain `unittest.TestCase` there doesn't load them at all (logic without GTK is tested in `tests/`). 1.4.2 and 1.5.0 failed to build that way; `tests/test_without_gtk.py` runs the unit discovery again with PyGObject blocked.
- UI tests: `scripts/ui-tests.sh` runs `tests/ui` on a private Broadway display (or a headless Weston with `NOTTERIZMUS_UI_BACKEND=weston`), with config, data and Documents in a scratch folder, and fails if GTK or Python prints a warning. `tests/ui/broadway_input.py` is a stdlib WebSocket client for Broadway: it sends real key events (`support.real_key` / `real_type`, through GTK's full dispatch: use them for shortcuts, Escape, focus) and real mouse drags (`support.real_drag`, points as `(widget, x, y)` or window-surface `(x, y)`; `hold=True` keeps the button down until `release_mouse()`) and answers frame roundtrips paced at 60 Hz (without replies GTK's frame clock stalls and animations such as a revealer never finish; unpaced it paints frames no screen would show). Add a UI test for every UI bug fixed. Helpers are in `tests/ui/support.py`: `open_chapter`, `focus`, `press` (emits `key-pressed` on the widget's own controller with GTK's key names, e.g. Shift+z → `Z`), `type_text`, `settle`, `wait_for`, `record_frames`, `menu_choices`, `clipboard`.
- Each run is isolated: the runner gives it its own `XDG_RUNTIME_DIR` inside the scratch folder, which holds the display's socket (`broadway1.socket`) and the input client's (`gtk4-broadwayd --unixsocket`, `NOTTERIZMUS_UI_BROADWAY`). Several runs can go at once (other worktrees included) and nothing is left in the real runtime folder. Don't go back to a display number or TCP port picked from the shared one: broadwayd never removes its socket, so numbers ran out after about 40 runs per login, and two runs starting together took the same number.
- In UI tests, wait for a condition, never for a time (CR50): `ui.wait_for(cond, "what")` (fails the test after 10 s), `ui.settle()` (the outline laid out and still), or `ui.frames(n)` (n more painted frames: for a check that nothing changed, or a layout no state reports). Never `ui.pump(0.3)` or `time.sleep`, and no wait at all after something synchronous (a file operation, an action, a clipboard write, a popover's `popup()`). `tests/test_ui_waits.py` fails on any `ui.pump(` or `time.sleep(` in `tests/ui` outside `support.py`, `broadway_input.py` and `measure_drawings.py`. The app defers much of its work (focus from an idle callback, layout over the next frames, a chosen command after its dialog closed, autosave 800 ms later), and a fixed pause passes on an idle machine and fails on a busy one. The helpers already wait for what they start: `press`/`type_text`/`focus` until the editor has placed the cursor (`wait_editor`), `settle` until no row has moved for several frames, `real_key`/`real_drag` until the app has received the event; `past_double_click()` waits out what is left of GTK's double-click time since the last real press. Where the clock matters (Earlier Versions are named by the second), give the thing a time, as `test_backups` renames a copy to an older one, instead of waiting for the clock. Check a change to the suite under load: `taskset -c 0 scripts/ui-tests.sh` beside a few `taskset -c 0 python3 -c 'while True: pass'`.
- How real input is known to have arrived: `broadway_input.send` stamps every event with a time that only goes up; Broadway hands it on shifted by a constant (measured at start-up), and a capture-phase `EventControllerLegacy` on the window notes the newest stamp seen. While an `Adw.Dialog` or a popover is open, it gets key and pointer events first-hand (it is GTK's grab widget) and the window's controllers never see them, so the same watcher is put on the open dialog and popups before input is sent (`support._watch_modals`).
- The input client reports a button press with the buttons as they were before it (as X11 and Wayland do; GTK starts the drag's implicit grab only then), followed at once by a zero-distance pointer move carrying the new state. The Broadway server answers GDK's pointer query from the last state it was sent, and GTK uses that for the motion events it synthesizes after a layout change; without the extra move, such an event right after a press said "no button down" and the editor ended the drag.
- Every UI test starts from the same window state (`support.reset_window`, called by `UITestCase.setUp`: subclasses call `super().setUp()` first), fails if the app raised an exception in a callback during it (PyGObject only prints those; `support._watch_exceptions` collects them through `sys.excepthook`), and is stopped with every thread's traceback if it runs longer than `NOTTERIZMUS_UI_TEST_TIMEOUT` (180 s). All tests share one window and one scratch notes folder that only grows, so a test must not rely on a book's row being on screen in the chapter list (focus it first) or on being the only chapter of the default book.
- Performance of drawings (R29) and of the editor (phase 5 of CODE_REVIEW.md: Earlier Versions with 54 copies, a chapter of 500 items, Ctrl+Space in a book of 30 chapters): `NOTTERIZMUS_UI_WEBKIT=1 NOTTERIZMUS_UI_TEST_TIMEOUT=900 scripts/ui-tests.sh -p 'measure_*.py'` runs `tests/ui/measure_drawings.py` on the same private display and prints a report (`NOTTERIZMUS_MEASURE_OUT` also writes it as JSON; `NOTTERIZMUS_MEASURE_CHAPTER` adds a copy of a real chapter). Its name keeps it out of the normal UI run. Run it before and after a change meant to make drawings faster. That display draws without a GPU and in a small window, so it can't show how fast WebKit draws on the desktop: `scripts/measure-drawing-stroke.py` draws a stroke in the real drawing window on your own display and prints frames per second and CPU use.
- Adw dialogs keep counting as visible while they animate closed and give focus back when they finish: wait for `get_visible_dialog()` to be None before the next step.
- Never read the app's own clipboard synchronously from the main thread: the app supplies the data from the main loop, so it deadlocks (use `support.clipboard`).
- Ad-hoc scripts outside the runner: set `XDG_CONFIG_HOME`/`XDG_DATA_HOME` to a scratch dir and add `Gio.ApplicationFlags.NON_UNIQUE`; otherwise a running copy of the app just gets activated and the script exits silently.
- `NOTTERIZMUS_SNAPSHOT=out.png` renders the window to a PNG and quits; popovers need their own `Gtk.WidgetPaintable` render.
- Wayland: a window without keyboard focus can't own the clipboard, so system-clipboard tests from background windows fail; same-process clipboard reads work.

## Packaging and release
- Native source format `3.0 (native)`: versions have no `-revision`; rebuilds for another series use `1.0.0~<series>1`.
- `scripts/release.sh deb|source|ppa` builds from `git archive HEAD` (refuses a dirty tree) into `dist/` (git-ignored); signing uses the GPG key matching the `debian/changelog` maintainer email.
- Installed layout: code in `/usr/share/notterizmus/notterizmus/`, launcher `/usr/bin/notterizmus`, icons in hicolor PNG 16–512.
- lintian baseline: only pedantic `repeated-path-segment`. Man pages must stay ASCII (groff warns on Cyrillic or Roman-numeral characters).
- `install.sh` is a per-user developer launcher; remove it (`--uninstall`) before installing the package.
- Ubuntu releases (decided 2026-11-06; ROADMAP → Ubuntu support): the PPA for 26.04 and newer, each version copied to new series on Launchpad (R19), and a snap for 20.04–24.04 (R17). No native packages for 22.04 or 24.04. Today the PPA has `resolute` builds only.
